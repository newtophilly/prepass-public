# Bake-off: local embeddings vs BM25F

**240 SWE-bench Lite instances · k=20 · model: `Xenova/all-MiniLM-L6-v2`, quantized, path-only**

An outside review argued prepass was "defending a weaker paradigm" — that a small local embedding
model handles natural-language-to-code retrieval out of the box, where a lexical ranker needs a
hand-maintained glossary, and that the fair comparison is *manual lexical glossary vs compact
local vector matcher* rather than *lexical vs a full vector database*. Embedding only file paths
was their suggested cheap form of the idea. This tests exactly that.

## Result

| method | hit@1 | hit@5 | hit@20 | MRR | median query |
|---|---|---|---|---|---|
| **BM25F (prepass today)** | 27.5% | 52.1% | 70.8% | **0.383** | 110ms |
| dense paths alone | 15.0% | 35.4% | 56.7% | **0.247** | 33ms |
| hybrid (RRF fusion) | 30.0% | 56.7% | 73.8% | **0.422** | 156ms |

## Reading it

**Dense-alone loses, and not narrowly.** 0.247 against 0.383. The claim that a small local model
handles this out of the box is not supported for path-only embeddings — file paths are short,
formulaic and semantically thin, and a sentence embedder has little to work with.

**Hybrid wins, by a little.** +0.039 MRR and +3.0 points of hit@20 over lexical alone. This
matches Cursor's published A/B, which found semantic search layered on grep beat either alone —
two independent measurements agreeing is worth more than either.

**The costs the query-latency column hides:**

| | |
|---|---|
| paths embedded | 10,745 |
| one-off index | **18.2s** (1.7ms per path) |
| dependency | `@xenova/transformers`, **259 MB** of node_modules, plus model download |
| invalidation | every file change, forever |
| prepass today | 3 runtime deps, no model, no index, no download |

## Decision: not shipping it, not even as a default-off flag yet

+3 points of hit@20 does not buy 259 MB, an 18-second first run, and a cache to invalidate. More
importantly it would cost the property that makes this tool distinct from the large competitor in
this space: `npm i -g`, one config line, 110ms, nothing to download, usable inside a company.
Trading that for three points is a bad exchange.

The result is worth more as evidence than as a feature. "We tested embeddings and they were not
worth the weight" is a stronger position than "we did not try", and it is now measured rather
than asserted.

## Honest limits

- **Path-only is a floor for dense, not a ceiling.** Embedding file *contents* would very likely
  score better — and cost minutes of indexing, hundreds of MB of vectors, and re-embedding on
  every edit. Worth measuring before anyone claims dense can't win here.
- **MiniLM truncates at 256 tokens**; SWE-bench issues are far longer, so the query used the first
  1,200 characters. A model with a longer context might do better.
- One model, one fusion method (RRF), one corpus.

Reproduce: `node bench/bakeoff-embeddings.mjs` (needs `@xenova/transformers` installed separately —
deliberately not a dependency of prepass).
